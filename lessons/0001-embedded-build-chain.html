嵌入式构建链：从 .c 到 .bin

核心结论：Env 不负责把代码编译成某个文件。GCC 编译，SCons 编排，RT-Thread Env 准备环境和管理依赖。

.c + .h
  │ gcc -c
  ▼
.o        单个源文件的机器码和重定位信息
  │ linker + startup + libraries + link.lds
  ▼
.elf      完整、可调试、带地址和符号的固件
  │ objcopy -O binary
  ▼
.bin      原始烧录字节
  │ OpenOCD / STM32CubeProgrammer
  ▼
MCU Flash

每个工具做什么

工具作用
arm-none-eabi-gcc把 C 编译成 ARM 目标文件，并参与最终链接。
SCons读取 SConstruct/SConscript，决定调用哪些编译和链接命令。
RT-Thread Env准备 PATH、RTT_ROOT、SCons、pkgs 和 menuconfig 命令。
pkgs下载 CMSIS、HAL 等依赖包。
OpenOCD通过调试器把已经生成的镜像写入芯片。

RTT_ROOT 是什么

它是外部 RT-Thread SDK 的路径：LOCAL_USER_HOME\Desktop\RT-Thread\rt-thread-standard。自己的项目保存应用、配置和 BSP 适配；构建时通过 RTT_ROOT 找到 RT-Thread 的内核和构建框架。它类似引用一个 SDK，不等于复制或修改整个 SDK。
