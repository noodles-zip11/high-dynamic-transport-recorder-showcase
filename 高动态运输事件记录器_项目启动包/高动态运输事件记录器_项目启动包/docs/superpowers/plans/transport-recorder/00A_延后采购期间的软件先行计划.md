# 延后采购期间的软件先行 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在暂不购买开发板和传感器的条件下，用CLion、本机C测试和Python工具先完成可验证的软件基础，使硬件到货后主要精力用于板级差异与真实时序。

**Architecture:** 将硬件相关接口替换成行为受约束的fake实现，先开发纯算法、状态机、介质格式和协议编解码；PC结果是设计证据，不冒充STM32实测。所有模块保留窄接口，之后只替换总线、Flash和传输适配层。

**Tech Stack:** CLion、C11、SCons、GNU Arm GCC、本机C编译器、Python 3.12、pytest、PySide6、PyQtGraph。

## 0. 开发前Worktree门禁

在勾选本文件任何步骤前，先阅读仓库根目录的[AGENTS.md](../../../../../../AGENTS.md)和[版本管理工作流决策](../../../../../../docs/decisions/version-control-workflow.md)，并从最新`main`创建本阶段专用工作树：

```powershell
git rev-parse --is-inside-work-tree
git status --short
git worktree add ..\高动态运输事件记录器-worktrees\software-foundation -b feature/software-foundation main
Set-Location ..\高动态运输事件记录器-worktrees\software-foundation
git branch --show-current
git status --short
```

只有第一条输出`true`、当前分支为`feature/software-foundation`且两次状态检查均无输出时，才允许开发。若Git无效、`main`不存在、目录或分支已存在，立即停止并先运行`git worktree list`排查；不得靠删除、硬重置或切回`main`绕过。所有改动留在该工作树；通过软件测试和构建门禁后，经授权合入`main`，不等待实板验证。提交、推送和PR仍需显式授权。

## 1. 软件先行阶段能做什么

可以完成：

- 项目目录、构建脚本、CLion索引和静态检查；
- CRC、字节序、安全长度检查；
- FIFO字节流解析器，但只使用数据手册黄金向量；
- 固定块内存池、环形缓存、触发检测和事件状态机；
- 假NOR Flash、追加日志和掉电故障注入；
- TERP帧、流式解析、分块续传和Python CLI；
- 上位机离线导入、回放和错误文件展示；
- AI数据格式、特征接口和训练脚本骨架。

不能提前宣称完成：

- H743时钟、链接地址、DMA可达性和Cache一致性；
- ICM真实ID、SPI模式、FIFO水位和1 kHz无丢样；
- 板载Flash型号、擦除时间和真实掉电行为；
- USB枚举、CAN电气、RTC保持和功耗；
- 真实运输数据上的AI效果。

## 8. CLion中的日常循环

每次开发按以下顺序：

1. 在CLion中写一个失败测试；
2. 用内置Terminal运行最窄测试脚本；
3. 手敲最小实现；
4. 重新运行最窄测试；
5. 运行全部本机测试；
6. 更新`docs/learning-log/`，记录错误和解释。

CLion的绿色索引和语法检查不是构建证据；最终以脚本退出码和测试报告为准。
