# 硬件采购与到货验收 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在软件先行阶段出口通过后，以最低首批成本取得可追溯的H743和ICM硬件，并证明供电、调试、时钟和存储接口真实可用。

**Architecture:** 当前先做候选商品与资料归档，不立即下单；达到明确触发条件后再分批采购，首批只覆盖平台与单IMU闭环。每块板建立库存记录、原理图版本和实测ID；板卡验收失败时退换，不通过修改软件适配错误商品。

**Tech Stack:** STM32H743VIT6开发板、ICM-42688-P模块、SWD调试器、万用表、STM32CubeProgrammer、可选逻辑分析仪。

## 2. 下单时首批只买什么

### 必买

- STM32H743VIT6开发板一块，板价不超过200元；
- ICM-42688-P模块一块，必须引出SPI和中断；
- 2.54 mm排针、短杜邦线或小洞洞板；
- USB数据线，必须确认能传数据；
- 如果现有SWD调试器实测不能连接H7，再购买新的调试器。

### 首批不买

- ADXL375；
- CAN收发器；
- 自研PCB；
- 锂电池充电板；
- OLED、GPS和蜂鸣器。

这些器件分别在可靠日志、AI/OTA或最终集成通过后采购。

## 5. 断电检查

- [ ] 用万用表确认5 V与GND没有近似短路。
- [ ] 确认3.3 V与GND没有近似短路。
- [ ] 对照原理图找到SWDIO、SWCLK、NRST、3.3 V和GND。
- [ ] 确认板上跳帽和BOOT0处于正常Flash启动位置。
- [ ] 第一次上电不连接传感器，只给主控板供电。

预期：没有器件快速发热，没有明显异味，3.3 V电源在万用表允许误差内稳定。

## 6. SWD连接和芯片确认

- [ ] **Step 1: 检查CubeProgrammer能看到调试器**

```powershell
STM32_Programmer_CLI.exe -l
```

Expected：列出一个SWD调试器序列号。若命令不存在，先完成开发环境计划。

- [ ] **Step 2: 连接MCU**

```powershell
STM32_Programmer_CLI.exe -c port=SWD mode=UR reset=HWrst
```

Expected：输出设备名称、Device ID、Flash size和连接速度；保存完整文本。

- [ ] **Step 3: 连续连接十次**

重复执行连接命令十次。任何一次随机失败都先检查供电、复位、线长和调试器，不进入BSP开发。

- [ ] **Step 4: 更新库存文件**

把MCU丝印、Device ID、Flash size和十次连接结果写入`board_inventory.md`。

## 10. 常见错误

- SWD偶发失败：优先缩短线、降低SWD频率、检查NRST，不先改固件。
- USB线只能充电：换明确支持数据的线。
- 板卡被卖家称为“2 MB”但芯片后缀是VG：以芯片后缀和CubeProgrammer结果为准。
- ICM无响应：先确认CS和供电，再检查SPI模式，不立即怀疑芯片损坏。
