# ICM-42688-P驱动与DMA采集 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以可测试的分层驱动稳定采集ICM-42688-P六轴原始数据，并证明1 kHz采样、FIFO、中断和DMA链路没有静默丢样。

**Architecture:** SPI总线、芯片寄存器驱动、FIFO解析、采集服务四层分离。中断只发信号，线程负责DMA和解析；采样块来自固定内存池，禁止在高频路径动态分配。

**Tech Stack:** ICM-42688-P、STM32H743 SPI+DMA、RT-Thread device、C11、Ceedling或本机C测试、逻辑分析仪。

## 4. 最小通信闭环

第一步只做三件事：

1. 软复位；
2. 读取WHO_AM_I；
3. 读取一个稳定寄存器并打印。

新增MSH命令：

```text
imu probe
imu regread <address>
imu regwrite <address> <value>
```

写寄存器命令仅在调试构建启用，并禁止写保留寄存器。

- [ ] 连续读取器件ID 1000次，无错误。
- [ ] 用逻辑分析仪检查CS、时钟极性/相位和读写位。
- [ ] 保存一次正确事务截图和解码结果到 `evidence/phase04/`。

## 5. 配置低速轮询模式

先不用FIFO和DMA：

- 加速度计：±16 g，1 kHz；
- 陀螺仪：±2000 dps，1 kHz；
- 低噪声模式；
- 具体滤波带宽依据数据手册选择并写入决策记录。

- [ ] 初始化后逐个读回关键寄存器，与期望掩码比较。
- [ ] 静止放置10秒，输出均值、标准差、最小值和最大值。
- [ ] 分别将六个面朝上，检查重力轴符号和量级。
- [ ] 轻轻旋转板卡，确认三轴陀螺仪响应方向。

不要急于做“校准”。先区分零偏、噪声、比例系数、轴不正交和安装方向。

## 6. FIFO解析先在PC测试

定义与硬件无关的解析接口：

```c
typedef struct {
    int16_t accel[3];
    int16_t gyro[3];
    int16_t temperature;
    uint16_t sensor_timestamp;
    uint8_t status;
} imu_raw_sample_t;
```

- [ ] 从数据手册手工构造一个完整FIFO包作为黄金向量。
- [ ] 测试大端/小端组合、跨缓冲区包、残缺包、无效头和溢出标志。
- [ ] 解析器返回“消费字节数、产生样本数、错误原因”。
- [ ] 对输入长度0到最大包长做边界测试。

本机测试命令由第二阶段脚本统一封装，例如：

```powershell
pwsh tools/test_native.ps1 -Suite icm42688p_fifo
```

期望：所有用例通过；解析器不得读取输入边界之外的内存。

## 7. 中断、FIFO水位与DMA

推荐数据路径：

```text
IMU FIFO达到水位
  -> INT1 ISR记录时间并释放信号量
  -> acquisition线程读取FIFO计数
  -> SPI DMA搬运到D2 SRAM
  -> DMA完成回调释放消息
  -> 线程解析并写入sample_block
```

- [ ] ISR中不打印、不解析、不等待SPI。
- [ ] 设置FIFO水位，例如16或32个样本，以总线效率与延迟实测决定。
- [ ] DMA缓冲区放入BSP定义的 `.dma_buffer` 段并32字节对齐。
- [ ] 对FIFO计数设置上限，异常值不得导致缓冲区越界。
- [ ] DMA超时后复位SPI事务，但保留错误计数和事件标记。

定义采集统计：

```text
irq_count
dma_start_count
dma_timeout_count
fifo_overflow_count
sample_count
sequence_gap_count
max_service_latency_us
max_fifo_depth
```

## 8. 固定样本块和背压

`sample_block_t` 建议包含：

```text
block_sequence
first_monotonic_us
sample_period_ns
sample_count
flags
raw_samples[N]
```

- [ ] 用固定内存池创建样本块，数量由预触发时间和消费者最坏延迟计算。
- [ ] 生产者拿不到空闲块时，记录背压错误，不悄悄覆盖未知数据。
- [ ] 块所有权只允许 `FREE -> FILLING -> READY -> FREE`。
- [ ] 在断言构建中检测重复释放和非法状态跳转。

亲手计算：若每个样本16字节、1 kHz、保存10秒预触发，需要多少原始内存？再考虑块头、对齐和双缓冲余量。

## 9. Cache一致性对照实验

- [ ] 在DMA区non-cacheable配置下运行并记录CRC。
- [ ] 临时启用Cache但故意不做维护，仅在受控测试中观察错误表现。
- [ ] 正确加入clean/invalidate或恢复non-cacheable策略后再次记录CRC。
- [ ] 将结论写入 `docs/decisions/dma-cache-policy.md`。

这一步必须亲手做，因为H7“偶发旧数据”往往不是传感器坏，而是Cache一致性错误。

## 11. 常见错误与学习检查

常见错误：SPI模式错误、CS提前释放、FIFO包头理解错误、ISR工作过重、DMA区落在DTCM、Cache没维护、逐样本动态分配、用串口逐条打印拖垮采集。

你应能解释：

- 为什么先轮询再上FIFO和DMA？
- 为什么FIFO解析必须能在PC上测试？
- 水位越大为什么效率更高但延迟也更高？
- 中断时间戳和传感器时间戳各解决什么问题？
- 怎样证明“30分钟无丢样”，而不是凭曲线看起来连续？
