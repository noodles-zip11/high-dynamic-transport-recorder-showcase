# 预触发缓存与最小事件闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在尚未接入外部Flash和GUI前，完成“持续采样—触发—保留触发前后数据—导出—回放”的最小事件闭环。

**Architecture:** 采集服务生成不可变样本块，预触发环形缓存持有最近数据；触发管理器只记录事实和状态，事件组装器冻结所需块并追加后触发数据，最后通过调试串口导出到PC。

**Tech Stack:** RT-Thread IPC、固定内存池、C11、Python 3.12、pytest、NumPy、Matplotlib。

---

## 1. 明确最小事件定义

本阶段的事件不是AI判断，也不是完整产品格式。触发条件先用可解释规则：

- 任意加速度轴绝对值超过阈值；或
- 合加速度超过阈值；
- 连续满足指定样本数以抑制单点毛刺；
- 触发后进入保持时间，避免同一冲击形成大量重复事件。

本次已确定为 1 秒预触发（25 块）和 2 秒后触发（50 块）；重复触发可延长到最多 3 秒后触发，因此总窗口最多 4 秒。长于上限的事件带 `DURATION_CAPPED`，不无限占用 RAM。

在 `docs/decisions/minimal-trigger.md` 亲手写清：

```text

阈值：
连续样本数：
预触发时长：
后触发时长：
合并窗口：
选择依据和试验结果：
```

模块规则：

- 事件组装器管理状态和所有权；
- 导出模块只序列化已经完成的事件。

## 3. 先计算RAM预算

- [ ] 从04阶段取得真实 `sizeof(imu_raw_sample_t)` 和 `sizeof(sample_block_t)`。
- [ ] 计算每秒字节数。
- [ ] 计算10秒预触发和20秒后触发所需字节数。
- [ ] 加入DMA双缓冲、队列、线程栈和模型预留。
- [ ] 与链接器 `.map` 中的可用D1/D2 SRAM比较。

把公式和结果写进 `docs/decisions/ram-budget.md`。若预算不够，优先调整事件时长、采样格式或外部SDRAM方案；不要先无依据降低采样率。

## 4. 环形缓存测试优先

先写测试，再写实现：

- [ ] 空环读取返回明确状态。
- [ ] 未绕回时保持顺序。
- [ ] 写满后覆盖最旧块并正确释放旧引用。
- [ ] 冻结事件时，被引用块不会被覆盖或释放。
- [ ] 32位序列号回绕时，顺序比较仍正确。
- [ ] 预触发窗口不足时，事件带有 `PRETRIGGER_SHORT` 标记。

建议接口表达所有权：

```c
bool pretrigger_push(sample_block_ref_t block);
size_t pretrigger_snapshot(sample_block_ref_t *out, size_t capacity);
void sample_block_retain(sample_block_ref_t block);
void sample_block_release(sample_block_ref_t block);
```

不要返回内部数组指针给调用者长期持有。

## 5. 触发检测器

- [ ] 输入使用原始整数或固定点，避免MCU与PC浮点行为差异。
- [ ] 显式处理绝对值溢出，例如最小负数。
- [ ] 合加速度可先比较平方值，避免高频开平方。
- [ ] 单元测试边界：阈值下、等于阈值、阈值上、连续计数中断、保持窗口。
- [ ] Python写同一参考算法，用黄金CSV对照C结果。

触发输出应至少包含：

```text
trigger_type
trigger_monotonic_us
sample_sequence
peak_raw
threshold_raw
axis_mask
```

## 6. 事件状态机

推荐状态：

```text
IDLE
  -> POST_TRIGGER_CAPTURING
  -> READY_FOR_EXPORT
  -> EXPORTING
  -> IDLE
```

触发瞬间，组装器先快照预触发块，再累计后触发块。

- [ ] 在 `event_assembler.h` 中定义状态和每个事件的唯一ID。
- [ ] 对每个状态允许的输入事件写表格。
- [ ] 非法状态跳转触发断言并递增错误计数。
- [ ] 后触发期间再次触发时，第一版采用“延长窗口并记录子触发”。
- [ ] 设置最大事件时长，持续振动不能永久占住全部内存。
- [ ] 导出超时或主机断开后，事件必须能释放并回到IDLE。

本阶段不并行保存多个大事件；先把单事件资源所有权做对，再在后续阶段扩展队列。

## 7. 调试导出格式

为最小闭环定义简化但严格的二进制格式：

```text
magic: 4 bytes = EV01
format_version: u16 little-endian
header_length: u16
event_id: u32
sample_rate_hz: u32
pre_sample_count: u32
post_sample_count: u32
payload_length: u32
payload_crc32: u32
payload: packed imu_raw_sample_t array
```

- [ ] C端用显式逐字段编码，不直接发送含填充的结构体。
- [ ] Python端先验证magic、长度和CRC，再解释payload。
- [ ] 在 `docs/protocol/debug_event_v1.md` 画字节偏移表。
- [ ] 用同一黄金文件验证C端和Python端。

说明：该格式仅用于第五阶段闭环。第八阶段会引入正式TERP帧，不要让临时格式扩散到GUI和长期存储。

## 8. 主机捕获和回放脚本

执行方式：

```powershell
.\.venv\Scripts\python.exe host/tools/capture_debug_event.py --port COM7 --output data/raw/event_0001.ev01
.\.venv\Scripts\python.exe host/tools/plot_event.py data/raw/event_0001.ev01 --output evidence/phase05/event_0001.png
```

脚本要求：

- 串口号和输出路径必须显式给出；
- 超时、CRC错误和版本不支持有不同退出码；
- 同时导出原始二进制、元数据JSON和曲线PNG；
- 图中标出触发点、阈值、预触发和后触发区域；
- 不自动修改原始数据。

## 9. 板上调试命令

新增MSH命令：

```text
event status
event arm
event trigger_test
event export
event clear
```

- `trigger_test` 只注入触发事实，不伪造传感器样本。
- `clear` 在事件正在导出时必须拒绝。
- `status` 输出内存池空闲块、环形缓存深度、当前状态和最近错误。

## 10. 故障注入

- [ ] 在预触发缓存尚未填满时触发。
- [ ] 恰好在块边界触发。
- [ ] 后触发期间连续触发10次。
- [ ] 导出中途拔掉串口或复位主机工具。
- [ ] 人为让消费者变慢，验证背压计数和资源释放。
- [ ] 修改文件一个字节，Python必须报CRC错误。
- [ ] 连续执行100次测试触发，内存池空闲数量最终恢复到初始值。

## 11. 实物事件试验

安全前提：开发板固定在泡棉或小盒内，线缆留有余量；不摔裸板、不让电池受冲击。

- [ ] 静止记录，确认无误触发或记录误触发率。
- [ ] 手持轻敲桌面，产生低强度事件。
- [ ] 对保护盒做可重复小高度跌落，不追求破坏性冲击。
- [ ] 每类至少记录10次，命名包含日期、动作和序号。
- [ ] 回放曲线能看到触发前稳定段、冲击峰值和衰减段。

## 12. 验收与学习检查

通过标准：

- 单元测试覆盖环回、状态机和CRC边界；
- 板上100次测试触发无内存泄漏；
- 至少三类真实动作可以导出并回放；
- 每个事件同时含触发前和触发后数据；
- 错误文件不会被当成正常事件展示。

你应能解释：

- 环形缓存覆盖旧块时，为什么引用计数或所有权特别重要？
- 预触发为何无法在触发后“补采”？
- 为什么不直接把C结构体通过串口发送？
- 为什么持续振动需要最大事件时长？
- 什么证据可以说明最小事件闭环真的闭合？
