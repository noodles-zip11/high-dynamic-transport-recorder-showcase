# 系统验证、成果整理与面试 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用可重复测试和可审查证据证明记录器的可靠性、嵌入式深度与AI价值，并整理成求职作品集，而不是只有演示视频和功能清单。

**Architecture:** 建立需求到测试到证据的追踪矩阵；自动化测试输出机器可读结果，实物试验保留原始数据、配置和环境；README、技术报告和面试叙事只引用已经通过的证据。

**Tech Stack:** PowerShell/Python测试编排、pytest、本机C测试、硬件在环串口控制、示波器/逻辑分析仪、CSV/JSON/Markdown报告、Git版本标识。

## 0. 开发前Worktree门禁

在修改验证脚本、指标、证据或作品集材料前，先阅读仓库根目录的[AGENTS.md](../../../../../../AGENTS.md)，并创建本阶段专用工作树：

```powershell
git rev-parse --is-inside-work-tree
git status --short
git worktree add ..\高动态运输事件记录器-worktrees\system-verification -b feature/system-verification main
Set-Location ..\高动态运输事件记录器-worktrees\system-verification
git branch --show-current
git status --short
```

只有第一条输出`true`、当前分支为`feature/system-verification`且两次状态检查均无输出时，才允许开发。若Git无效、`main`不存在、目录或分支已存在，立即停止并先运行`git worktree list`排查；不得删除或硬重置来绕过。报告只能引用真实运行证据，提交、推送和PR仍需显式授权。

## 3. 分层测试金字塔

### 本机单元测试

- FIFO解析、环形缓存、状态机；
- Flash事务与掉电仿真；
- TERP/ISO-TP流式解析；
- 特征与模型黄金向量；
- 上位机仓库和状态机。

### 板级测试

- 时钟、内存、Cache/DMA；
- 传感器通信与采样率；
- Flash几何和写擦；
- USB/CAN电气与协议；
- RTC、看门狗和复位原因。

### 系统测试

- 触发、记录、AI、下载、回放全链路；
- 掉电、断连、存储满、传感器断线；
- 长稳、并发和性能压力。

先运行最窄测试，失败时不要用全系统反复试错替代定位。

## 4. 统一测试命令

最终提供：

```powershell
pwsh tools/selfcheck.ps1
pwsh tools/build_firmware.ps1 -Configuration Release
pwsh tools/test_native.ps1
.\.venv\Scripts\python.exe -m pytest host/tests ai/tests -q
pwsh tools/hil_smoke.ps1 -Port COM7
pwsh tools/package_evidence.ps1 -RunId 20260713_release_candidate
```

每个脚本：失败返回非0；输出工具版本；写JUnit/JSON或CSV结果；不靠人工阅读绿色文字判断成功。

## 5. 核心可靠性验收

- [ ] 1 kHz采集30分钟：序号缺口0，FIFO溢出0。
- [ ] 完整系统72小时：无异常复位、内存池泄漏和持续增长队列。
- [ ] 事件触发100次：每次含预/后触发并可回放。
- [ ] Flash随机掉电100次：旧提交记录无丢失。
- [ ] USB随机断连20次：事件下载可续传且最终CRC正确。
- [ ] TERP随机破坏1000轮：无崩溃、无越界、可重新同步。
- [ ] OTA安装随机断电30次：0变砖，可回滚或救援。
- [ ] CAN bus-off 20次：按策略恢复或进入明确故障状态。

若硬件条件暂不支持CAN，作品集明确标为“接口与软件测试完成/实线验证未完成”，不能写成全部完成。

## 6. 性能预算报告

记录场景：待机、1 kHz采集、事件写入、USB下载、AI推理、CAN压力。

每个场景测：

- CPU占用或任务运行时间；
- 最坏中断/服务延迟；
- Flash和RAM占用；
- 内存池最低余量；
- 功耗平均值与峰值；
- 温度或长时间漂移；
- 数据吞吐和错误计数。

将“估算”“工具静态分析”“实板测量”分栏，不能混写。

## 12. 面试叙事

准备5分钟主线：

```text
运输过程缺少可追溯证据

-> 追加日志解决掉电一致性
-> TERP统一USB/CAN通信
-> TinyML作为规则后的二级分类
-> 通过故障注入和长稳证明可靠性
```

每个难点按“现象—根因—方案—取舍—证据”讲。准备追问：为何不用Linux、为何不用F407、为何不直接存SD卡、AI为何不直接触发、CRC为何不安全、OTA如何防变砖。

## 13. 项目含金量判定

按完成程度分级：

- 只有传感器曲线和GUI：普通课程设计。
- 完成RTOS、DMA、预触发、可靠Flash和协议：较强嵌入式作品。
- 加入故障注入、OTA回滚、系统健康和72小时证据：高质量求职作品。
- 再有无泄漏数据划分、端侧量化一致性和相对基线收益：在AI时代有真实区分度。
- CAN FD/ISO-TP实线验证和自制PCB是加分项，不应挤占核心可靠性闭环。

决定含金量的不是主控更贵、模块更多，而是问题真实、架构有取舍、实现可解释、测试可复现、结论不夸张。
